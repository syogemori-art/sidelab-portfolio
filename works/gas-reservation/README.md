# Googleフォームの予約を自動で管理（サンプル）

> **これはサイドラボのポートフォリオ用サンプルです。** 店名（さくら整体院）・お客様情報などはすべて架空です。

Google フォームで受け付けた予約を、**自動で一覧に記録 → 確認メール → カレンダー登録 → 前日リマインド** まで行うツールです。
同じ時間帯に予約が重なった（ダブルブッキング）ときは自動で確定せず、お店側にだけ知らせます。
Google Apps Script（GAS）で動くので、月額費用や予約システムの契約はいりません。

---

## どんな悩みを解決するか

| よくある悩み | このツールでは |
|---|---|
| 予約が入るたびに、表に転記してカレンダーに入れて確認メールを書いている | フォーム送信と同時に **すべて自動**（記録・カレンダー登録・確認メール） |
| うっかり同じ時間に2件予約を受けてしまった | 同じ枠の予約や、カレンダーの私用予定と重なる予約を **自動で検知**。お客様へは確定メールを送らず、お店に通知 |
| 前日のリマインド連絡を忘れる・手間がかかる | **毎朝自動で**、翌日のお客様にリマインドメール |
| 有料の予約システムは高い・使いこなせない | 普段の Google フォーム・スプレッドシート・カレンダーだけで動く（追加費用 0円） |

**想定例**：1日5件の予約がある場合、転記・カレンダー登録・確認メール・リマインドで 1日 約50分 → 約0分（自動）。
※数値は想定例です。予約数や運用によって変わります。

---

## できること

- フォームから予約が入ると、「予約管理」シートに1行追加（予約ID・ステータス付き）
- 予約の内容をチェックして、自動で振り分け
  - **問題なし** → Google カレンダーに予定を登録し、お客様へ **確認メール**（ステータス「確定」）
  - **問題あり** → ステータス「要確認（理由）」で赤く色付けし、**オーナーにメールで通知**（お客様には「確認して改めて連絡します」という仮受付メール）
- チェックする内容
  - 同じ時間帯の「確定」済み予約と重なっていないか（**ダブルブッキング**。1枠の受け入れ人数も設定可）
  - カレンダーに手入力した予定（私用・休憩など）と重なっていないか
  - 定休日・営業時間外・過去の日時ではないか
- 毎朝決まった時間に、翌日の予約のお客様へ **リマインドメール**（送信済みの人には再送しない）
- メニューから「選択した予約を確定にする」「キャンセルにする（カレンダーの予定も削除）」が使える
- 2件の予約がほぼ同時に届いても、順番に処理して重複を見逃さない仕組み（ロック）つき

## 導入手順（15分ほど）

パソコンのブラウザ（Google Chrome がおすすめ）で作業してください。

### 1. スプレッドシートを用意する
1. [Google スプレッドシート](https://sheets.google.com) で「空白のスプレッドシート」を作成し、「予約管理」など分かりやすい名前をつけます。
   - すでに予約フォームをお持ちの場合は、フォームの「回答」タブ →「スプレッドシートにリンク」で作られたスプレッドシートを使ってください。

### 2. プログラムを貼り付ける
1. スプレッドシートの上のメニュー **「拡張機能」→「Apps Script」** をクリックします。
2. `コード.gs` の中身をすべて消して、このフォルダの **`Code.gs` の中身を貼り付け** ます。
3. 「ファイル」の横の **「＋」→「スクリプト」** で `Setup` という名前のファイルを作り、**`Setup.gs` の中身を貼り付け** ます。
4. **💾（プロジェクトを保存）** を押します。

### 3. 設定を書き換える
`Code.gs` の上のほうにある `CONFIG` の中を、お店に合わせて書き換えて保存します（下の「[設定項目](#設定項目)」参照）。
最低限、**`SHOP_NAME`（店名）** だけ変えれば動きます。

### 4. タイムゾーンを確認する（大切）
1. 編集画面の左端の **⚙（プロジェクトの設定）** を開きます。
2. 「タイムゾーン」が **「(GMT+09:00) 日本標準時 - 東京」** になっているか確認します。
3. （任意）「"appsscript.json" マニフェスト ファイルをエディタで表示する」にチェックを入れ、表示された `appsscript.json` にこのフォルダの `appsscript.json` を貼り付けると、タイムゾーンと権限がまとめて設定されます。
4. スプレッドシートの **「ファイル」→「設定」** の「タイムゾーン」も「東京」になっているか確認します。

### 5. フォームを用意する
1. スプレッドシートのタブに戻り、**ページを再読み込み**（F5キー）します。上のメニューに **「予約管理」** が出てきます。
2. **「予約管理」→「サンプルの予約フォームを作成」** をクリックします。
3. 初回だけ承認画面が出ます。下の「[初回の承認画面について](#初回の承認画面について)」を見ながら許可し、もう一度同じメニューを押します。
4. フォームが作られ、お客様に案内する **回答用URL** が表示されます。
   - **自前のフォームを使う場合**：質問のタイトルを `CONFIG.FIELDS` と同じ文字にしてください（例：「お名前」「メールアドレス」「ご希望日」「ご希望の時間」）。「ご希望の時間」は「10:00〜11:00」のような選択肢にしてください。

### 6. 自動実行を登録する
1. **「予約管理」→「初期設定（自動実行を登録）」** をクリックします。
2. 「初期設定が完了しました」と出れば準備完了です。これ以降、フォームに予約が入るたびに自動で動きます。

### 7. 動作を試す
1. **「予約管理」→「テスト予約を1件入れる」** を押すと、明日以降の最初の枠にテスト予約が入ります。
   - 確認メールは **ご自身のアドレス** に届きます。カレンダーにも予定が入ります。
2. もう一度 **「テスト予約を1件入れる」** を押すと、同じ枠への2件目になるので「**要確認（重複予約）**」になり、オーナー宛ての通知メールが届きます。
3. 試し終わったら、テストの行を選んで **「選択した予約をキャンセルにする」** を押すと、カレンダーの予定も消えます（行はシートに残るので、不要なら行ごと削除してください）。

## 設定項目

`Code.gs` の先頭 `CONFIG` で変更できます。

| 項目 | 初期値 | 説明 |
|---|---|---|
| `SHOP_NAME` | `'さくら整体院（架空）'` | 店名。メールの差出人名・本文に使います |
| `OWNER_EMAIL` | `''`（空欄） | 重複などの通知を受け取るアドレス。空欄なら設定した人の Gmail |
| `CALENDAR_ID` | `''`（空欄） | 予定を入れるカレンダーのID。空欄ならメインのカレンダー。予約専用カレンダーを使う場合は、カレンダーの「設定と共有」→「カレンダーの統合」にある ID を入れます |
| `SLOT_MINUTES` | `60` | 1枠の長さ（分） |
| `OPEN_TIME` / `LAST_START_TIME` | `'10:00'` / `'17:00'` | 最初の枠と最後の枠の開始時刻 |
| `CLOSED_WEEKDAYS` | `[3]` | 定休日（0=日 1=月 … 6=土）。水・日休みなら `[0, 3]`、休みなしなら `[]` |
| `CAPACITY_PER_SLOT` | `1` | 同じ時間に受けられる人数 |
| `CHECK_CALENDAR_CONFLICTS` | `true` | カレンダーの他の予定と重なる予約も「要確認」にするか |
| `REMINDER_HOUR` | `9` | 前日リマインドを送る時間帯（9 = 毎朝9時台） |
| `SEND_PENDING_NOTICE` | `true` | 要確認のとき、お客様に「確認して改めて連絡します」メールを送るか |
| `NOTIFY_OWNER_EVERY_BOOKING` | `false` | 問題のない予約もオーナーに通知するか |
| `FIELDS` | （質問名） | フォームの質問タイトル。自前のフォームに合わせます |
| `MENUS` | （3種類） | サンプルフォームに表示するメニュー |

メールの文面は、`Code.gs` の `MAIL`（確認メール・仮受付メール・リマインド）で変更できます。`{お名前}` `{日時}` などは自動で差し込まれます。

### 予約管理シートの列

`予約ID / 受付日時 / お名前 / メールアドレス / 電話番号 / 予約日 / 開始 / 終了 / メニュー / ご要望 / ステータス / カレンダー予定ID（非表示） / 確認メール / リマインド / メモ`

- ステータスは「確定」「要確認（理由）」「キャンセル」のいずれかです。
- 「要確認」になった予約は、お客様と日時を調整したあと、必要なら「予約日」「開始」「終了」を書き換え、行を選んで **「選択した予約を「確定」にする」** を押すと、カレンダー登録と確認メールが行われます。

## 初回の承認画面について

初めて実行するとき、Google から「このアプリがアカウントへのアクセスを求めています」という画面が出ます。
これは **ご自身で作ったプログラムに、ご自身のデータを扱う許可を出す** ための確認です。

1. 「権限を確認」→ ご自身の Google アカウントを選びます。
2. 「**このアプリは Google で確認されていません**」と出たら、左下の **「詳細」** →「**（プロジェクト名）（安全ではないページ）に移動**」を押します。
   - 個人で作ったプログラムには必ず出る表示で、ウイルスなどの意味ではありません。
3. 許可の内容を確認して **「許可」** を押します。

| 求められる権限 | 使いみち |
|---|---|
| スプレッドシートの表示・編集 | 予約管理シートへの記録 |
| Google フォームの表示・編集 | サンプルフォームの作成 |
| カレンダーの表示・編集 | 予約の登録、重なる予定のチェック、キャンセル時の削除 |
| ユーザーに代わってメールを送信 | 確認メール・リマインド・オーナーへの通知 |
| 自動実行（トリガー）の管理 | フォーム送信時・毎朝の自動実行の登録 |
| メールアドレスの表示 | 通知先（ご自身のアドレス）を調べる |

## 注意点

- **メールの送信上限**：Apps Script から送れるメールは、無料の Google アカウントで **1日あたり約100通**、Google Workspace（有料）で約1,500通です。確認メール・リマインド・通知の合計で数えます。上限に近づくとお客様へのメールは送らずに止まり、「メモ」欄とオーナーへの通知でお知らせします。目安として、1日の予約が40件を超える場合は Google Workspace をおすすめします。
- **自動実行の持ち主**：トリガーは「初期設定」を実行した人のアカウントで動きます。メールの差出人もその人の Gmail になります。そのアカウントを削除・停止すると止まります。
- **初期設定は1回でOK**：何度実行しても二重登録にはなりませんが、設定（`REMINDER_HOUR` など）を変えたときはもう一度実行してください。
- **フォームの質問名を変えたとき**は、`CONFIG.FIELDS` も同じ文字に直してください。読み取れない場合は「要確認（日時が読み取れません）」になり、オーナーに通知されます。
- **リマインドの時刻**：Google の仕様で「9時台」のように1時間の幅の中で実行されます（9:00ちょうどとは限りません）。
- **カレンダーの予定とのチェック**（`CHECK_CALENDAR_CONFLICTS`）は、終日の予定は対象外です。
- お客様へのキャンセル連絡は自動では送りません。キャンセル時はお店からご連絡ください。
- エラーが起きたときは、オーナーにメールで内容が届きます。また、Apps Script 画面左の「実行数」でも履歴を確認できます。
